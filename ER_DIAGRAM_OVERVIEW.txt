                    ER DIAGRAM OVERVIEW - PROJECT REPORT
                Student Placement Cell DBMS System
================================================================================

SYSTEM ARCHITECTURE:
The database contains 12 core entities with 20+ relationships implementing a 
hierarchical structure with proper cardinality notation (1:1, 1:N, M:N).

================================================================================
ENTITY LAYERS:
================================================================================

LAYER 1 - ADMINISTRATION:
├─ CGDC_ADMIN (Top-level administrators)
└─ PLACEMENT_COORDINATOR (Manages placement process)

LAYER 2 - AUTHENTICATION:
└─ USER_ROLE (Polymorphic login system for all user types)

LAYER 3 - CORE BUSINESS ENTITIES:
├─ STUDENT (Students seeking placement)
├─ COMPANY (Recruiting companies)
└─ JOB_PROFILE (Job postings by companies)

LAYER 4 - TRANSACTION TRACKING:
├─ APPLICATION (Student applications to jobs)
├─ INTERVIEW (Interview scheduling and tracking)
├─ OFFER (Job offers to students)
└─ PLACEMENT_RECORD (Final placement confirmations)

LAYER 5 - SUPPORTING ENTITIES:
├─ RESUME (Student resume versions)
└─ STUDENT_SKILL (Skills inventory for students)

================================================================================
KEY RELATIONSHIPS:
================================================================================

ADMINISTRATIVE HIERARCHY:
  CGDC_ADMIN (1) ──supervises──> (N) PLACEMENT_COORDINATOR
  PLACEMENT_COORDINATOR (1) ──coordinates──> (N) STUDENT

STUDENT INTERACTIONS:
  STUDENT (1) ──applies_to──> (N) APPLICATION
  APPLICATION ──links──> JOB_PROFILE
  STUDENT (1) ──attends──> (N) INTERVIEW
  STUDENT (1) ──receives──> (N) OFFER
  STUDENT (1) ──uploads──> (N) RESUME
  STUDENT (1) ──possesses──> (N) STUDENT_SKILL

COMPANY OPERATIONS:
  COMPANY (1) ──posts──> (N) JOB_PROFILE
  JOB_PROFILE (1) ──receives──> (N) APPLICATION
  JOB_PROFILE (1) ──hosts──> (N) INTERVIEW

PLACEMENT FINALIZATION:
  STUDENT (1) ──secures_placement──> (N) PLACEMENT_RECORD
  COMPANY (1) ──hires_through──> (N) PLACEMENT_RECORD

================================================================================
CARDINALITY & CONSTRAINTS:
================================================================================

PRIMARY KEY - All entities use auto-increment INT for fast lookups

FOREIGN KEY CONSTRAINTS:
  ✓ STUDENT.coord_id → PLACEMENT_COORDINATOR.coord_id
  ✓ APPLICATION.(s_id, job_id) → (STUDENT, JOB_PROFILE)
  ✓ INTERVIEW.(s_id, job_id) → (STUDENT, JOB_PROFILE)
  ✓ OFFER.s_id → STUDENT.s_id
  ✓ PLACEMENT_RECORD.s_id → STUDENT.s_id
  ✓ PLACEMENT_RECORD.comp_id → COMPANY.comp_id
  ✓ CASCADE DELETE enabled for referential integrity

UNIQUE CONSTRAINTS:
  ✓ STUDENT.email (UNIQUE) - Alternative identifier
  ✓ USER_ROLE.username (UNIQUE) - Authentication uniqueness
  ✓ APPLICATION(s_id, job_id) - Prevent duplicate applications

DEPENDENCY TYPES:
  ✓ TOTAL DEPENDENCY: STUDENT depends on PLACEMENT_COORDINATOR
  ✓ PARTIAL DEPENDENCY: Some coordinators may have no students
  ✓ POLYMORPHIC REFERENCE: USER_ROLE serves multiple entity types

================================================================================
NORMALIZATION STATUS:
================================================================================

✓ 1NF: Atomic values (Fixed: Skills in JOB_REQUIRED_SKILL bridge table)
✓ 2NF: Full functional dependency (Single-column PKs ensure compliance)
✓ 3NF: No transitive dependencies (Calculated fields in views, not tables)

Result: FULLY NORMALIZED TO 3NF - No data redundancy, high consistency

================================================================================
ANALYTICAL VIEWS SUPPORTED:
================================================================================

  • Student Profiles (applications, interviews, placements count)
  • Placement Summary (department-wise statistics)
  • Company Statistics (hiring records, average packages)
  • Active Job Postings (real-time vacancy tracking)
  • Department Performance (placement rates by department)
  • Recruiter Rankings (company-wise hiring volume)

================================================================================
TRANSACTION SUPPORT:
================================================================================

Complex multi-step transactions implemented with ACID properties:
  ✓ Offer acceptance (Update offer, mark placed, reduce vacancy, record)
  ✓ Application processing (Create, track, interview scheduling)
  ✓ Placement recording (Multiple table updates with rollback capability)
  ✓ Pessimistic locking prevents concurrent offer conflicts
