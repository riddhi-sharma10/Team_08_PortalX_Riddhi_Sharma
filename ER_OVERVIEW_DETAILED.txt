The Student Placement Cell Database comprises 22 interconnected entities implementing a three-tier hierarchical structure: CGDC_ADMIN → PLACEMENT_COORDINATOR → STUDENT. The core placement pipeline tracks APPLICATION → INTERVIEW → OFFER → PLACEMENT_RECORD, with each student applying to multiple JOB_PROFILE entities posted by COMPANY. The schema achieves strict 3NF compliance through normalized bridge tables: JOB_REQUIRED_SKILL and JOB_ELIGIBILITY_BRANCH resolve multi-valued dependencies in job postings, VISIT_COVERED_STREAM tracks company visit coverage across departments, and RESUME_PARSED_KEYWORD enables granular keyword analysis. A polymorphic USER_ROLE table provides unified authentication for students, coordinators, and admins. Supporting entities include RESUME with ATS scoring, STUDENT_SKILL with proficiency levels, COMPANY_VISIT_HISTORY for placement analytics, NOTIFICATION for system-wide messaging, CHAT_MESSAGE for coordinator-student communication, and STATUS_AUDIT_LOG—auto-populated by database triggers to maintain a tamper-evident audit trail. All 22 tables employ auto-increment primary keys, strategic indexing on frequently-filtered columns (cgpa, status, dates, roles), and foreign key constraints with CASCADE delete to enforce referential integrity.
